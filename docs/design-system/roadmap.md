# Extension roadmap

Priority follows the current campaign workflow, not the breadth of the catalog. Effort is relative: S = one bounded component/consumer; M = several components or consumers; L = orchestration, multiple workflows or extensive accessibility validation. P0 is a task blocker; P1 precedes further reuse; P2 follows necessary coverage; P3 is optional. Dependencies refer to the new hierarchy.

## Later improvements: conditional or optional

| Component/pattern | User need | Atomic level | Dependencies | Priority | Effort | Acceptance criteria |
| --- | --- | --- | --- | --- | --- | --- |
| Token/layer/spacing completion | Keep future screens consistent without broad overrides | Foundations | Existing primitive palette and semantic v2 roles | P2 conditional | M | Inventory literal values by purpose; distinguish artwork dimensions from UI tokens; document structural/control/focus border roles, overlay layers and motion; migrate in bounded groups with screen checks. Do not tokenize every incidental value. |
| Dark theme / density modes | Support different viewing conditions or denser workspaces if research confirms demand | Foundations + templates | Complete foreground/background/status/focus token pairs, preference persistence | P3 optional | L | Theme scope includes every production surface/overlay/native control; respects system preference with explicit user override; contrast, imagery and reduced motion verified. A dark settings swatch alone does not qualify. |
| Global toast / notification queue | Receive non-blocking completion feedback across tasks when local feedback is insufficient | Molecule / organism | Async lifecycle, live-region and queue policy | P3 conditional | M | Deduplicate; avoid disappearing critical errors; actionable messages remain reachable; no repeated announcements; product need demonstrated before adding a new dependency. |
| Virtualized/searchable data interfaces | Keep large campaign/asset collections usable when measured volume warrants it | Organism | Pagination/filter model, selection, server query contract | P3 conditional | L | Measured performance threshold and dataset first; keyboard/screen-reader navigation and selection survive virtualized rows; maintain empty/error/loading behavior. |
| Booking, ratings, audience controls, slash-command/model composer | Enable workflows beyond the current brief-to-banner scope | Feature organisms / molecules | Product requirements, persistence/provider contracts, permissions | P3 optional | M–L | Validate a real user need and backend ownership first. Current SchedulingBlock, ratings, range and model controls stay explicitly exploratory. |
| Published package / visual regression / design-code mapping | Support multiple consuming apps or distributed designers | Tooling | Stable exports, semantic tokens, release policy, adopted shared components | P3 conditional | L | At least two genuine consumers; versioning/deprecation policy; screenshot baselines for supported states/viewports; no blanket migration before dependencies are known. Figma mapping is excluded from this task. |

Sequence: finish form/feedback/navigation contracts first, adopt them in real call sites, then extract page layouts. Optional control breadth must not outrank task recovery and reviewer accessibility. See [component contracts](components.md) for current support and constraints.
